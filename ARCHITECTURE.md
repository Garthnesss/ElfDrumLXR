# LXR Plugin — Architecture

## Big picture
```
DAW (Live/…) ── VST3/AU ──┐
Standalone ──────────────┤
                         ▼
              JUCE PluginProcessor
        ┌───────────────┼──────────────────┐
        ▼               ▼                  ▼
  Param bridge    Seq bridge         File layer
  (APVTS ⇄ CC     (host transport    (.SND/.PAT/
   replay into     → 96 ppq ticks     project IO,
   firmware        → seq_tick())      no FatFs)
   parser)              │                  │
        └───────────────┼──────────────────┘
                        ▼
              Engine wrapper (C API, lxr_*)
                        ▼
     Vendored firmware Core (patched copy):
     DSPAudio + FX + FxBus + MIDI + Sequencer
                        ▼
              Shim layer (HAL/GPIO/RNG/
              Cortex intrinsics/DWT/FatFs stubs)
                        ▼
        64-frame blocks @ 44,140 Hz ── resampler ──► host rate
        4 jack channels (DAC1 L/R, DAC2 L/R) ──► 2 stereo buses
```

## Components
- **vendor/** — Pinned clone of erica-synths/lxr-desktop-app (commit a43cd4f, Oct 20, 2026). Never edited directly; the build copies `Core/` into `build/src` and applies `patches/` (the PHX-D01 build pattern, which works).
- **patches/** — Numbered, commented patches against the vendor tree. Known so far: `01-oscillator-overflow-flag` (compute the ARM V flag in C — from PHX-D01, GPL, credited). Our own additions land here as discovery requires (expect: none for the DSP; the shim absorbs the rest).
- **shim/** — Host stand-ins for the STM32 world: `stm32f7xx_hal.h` (types, `__QADD16/__QSUB16/__SSAT/__PKHBT/__CLZ`, RNG → host random, GPIO array whose IDR bits are the output-jack detect switches, DWT stub), FatFs/USB header stubs. Starting point: PHX-D01's 70-line shim (GPL-3, credited), extended with the intrinsics it didn't need on Apple clang (`__SMLALD` family) and a portable `__fp16` mapping (`_Float16` or float, decided by golden-render comparison in Phase 0).
- **engine/** — A small C wrapper (`lxr_init`, `lxr_load_params`, `lxr_edit_params`, `lxr_hit`, `lxr_note`, `lxr_set_fader`, `lxr_render`, `lxr_morph_kit`). Follows PHX-D01's proven shape: kits are loaded by replaying the 247 parameter bytes as front-panel CCs into the firmware's own `frontParser_parseUartData` path (exactly how the hardware loads them), edits send only changed parameters. Kit morphing is the wrapper's one-shot `lxr_morph_kit(base, target, amount)` — the firmware's own interpolation copied into the wrapper, including its never-morph keep-set (audio routing 215–220, velocity destinations 149–154, LFO targets 167–172). The firmware's `presetManager` (and with it `preset_morph_tick`) is **not** compiled — it depends on FatFs — so nothing ticks; each morph amount is applied as a fresh interpolation + edit-diff. Applies PHX's two documented firmware-bug workarounds: parameter index 127 is skipped on load (stock code writes out of bounds — `midiParser_originalCcValues[65536]`), and NULL parameter pointers in the parameter array are pointed at scratch memory (readable flash on STM32, segfault natively).
- **plugin/** — JUCE 8 (CMake) `AudioProcessor` + editor. Formats: VST3, AU, Standalone. Owns threading: the engine is **not thread-safe** (single instance state, globals everywhere — same constraint PHX documents), so all engine calls happen on the audio thread; UI/MIDI-thread requests go through lock-free queues; kit loads are prepared off-thread and swapped on a block boundary.
- **param bridge** — APVTS parameters mirroring the 247 kit parameters (`kit000`–`kit246`; display names and ranges from the generated metadata — most are 0–127, but mod-target selectors run 0–228 and a few are 1-based) plus `morph` and the seven **performance faders** (`fader0`–`fader5`, `faderMaster`). The voice faders are NOT kit parameters: they drive the wrapper's `lxr_set_fader` path (the hardware performance-page faders); the master is a host-side trim in EngineHost. APVTS changes are translated into the same CC replay the kit loader uses, so there is exactly one parameter-entry path into the engine — the firmware's. **Morph as built:** the processor polls `morph` every block and computes the *desired kit* = `lxr_morph_kit(base kit, morph-target kit, morph × 255)`, then pushes only the differing bytes through the edit path. The morph target defaults to the previously loaded kit whenever a kit loads; since Oct 29, 2026 it is also explicitly settable — the processor exposes `loadMorphTargetFile()` / `getMorphTargetName()`, and the editor shows a "Morph target:" name with a "Load target .SND" button plus drag-and-drop onto the morph rows. Loading a target does not disturb the current kit; the current morph amount is simply re-applied against the new target.
- **seq bridge** — Drives the firmware sequencer from the host: DAW playhead/tempo → tick accumulator at 96 ppq → `seq_tick()` (the same call the firmware's timer ISR makes inside `soundengine_process()`), falling back to an internal clock in Standalone. Pattern/song state lives in the firmware's own `seq_patternSet`; the editor reads/writes it through the wrapper, never through a parallel model.
- **file layer** — `.SND` read/write (255 B desktop kits; reads 309 B module kits by ignoring the matrix tail), `.PAT` pattern-set read/write, `PROJnn` project-folder scan — ported from `presetManager.c`'s layouts with FatFs calls replaced by stdio. INIT kit ships from the firmware's own `initKit.c` (GPL, in-tree). Erica's factory kits are **not** bundled (they're a separate download on Erica's site); the browser imports user folders/cards.
- **voice slices (.lxv)** — A voice's kit parameters are an index *set* (the ParamEnums interleaves voices), defined by the generated metadata's per-voice assignment (`plugin/src/VoiceSlice.h`). `.lxv` voice-preset format: bytes 0–3 magic `LXV1`, byte 4 voice id (0–5), byte 5 slice length N, bytes 6..6+N−1 the slice bytes in ascending index order, then the 8-byte source kit name. A file whose N doesn't match the current metadata slice size for its voice is rejected (it came from a different firmware revision). Paste/Load apply the slice through the normal APVTS write path, so the bridge CC-replays the edit into the engine like any panel edit. Transfer is same-voice only: slice sizes differ per voice (36/37), so a slice is meaningless on another voice. Convention: voice files live in `~/Documents/ElfDrumLXR/voices/`.
- **UI metadata generation** — `tools/gen_pages.sh` compiles `tools/gen_pages.c` against the vendor tree: `parameter_dtypes[]` and `valueNames[]` are cut verbatim from `menu.c`, `modTargets[]` from `Cc2Text.c`, the ParamEnums symbol table is extracted from `Parameters.h` by a Python helper (anchors asserted), and `menuPages.h`/`MenuText.h` are compiled in directly (the extraction PHX-D01 proved for its web UI, reimplemented to emit C++). Output: the committed `plugin/src/ParamMetadata.generated.h` — every kit param's index, symbol, names, page/section (first menu occurrence wins; voice pages → open-hat page → FX → performance; unlisted params land in Global/System so coverage is exact), control type and range from the dtype, enum value-name lists, PM63 display offsets, randomise-guard flags, the panel order, the 229-entry mod-target name list, and the non-kit globals in their own table. Semantics follow how the **DSP consumes** values where the LCD disagrees: filter type is the DSP enum space (values 1–8 named LP…off, byte 0 = INIT's bypass, generated as a leading "-"), because `menu.c`'s LCD lookup is shifted one entry against `ResonantFilter.h`'s enum. LCD long-name typos/truncations ("Frequncy") are repaired by a small presentation-only map in the generator. Checks: `tools/check_metadata.py` (coverage/order/ranges-vs-INIT/name uniqueness) and the APVTS-side cross-check in `plugin_panel_test`. Regenerate when the vendor pin moves; never hand-edit the output.
- **per-instance engine (investigated Oct 29, 2026 — deferred)** — The engine remains a process-wide singleton. The full mutable-state surface was enumerated from the built library (nm): **157 writable symbols, 317,047 bytes** — dominated by `seq_patternSet` (233,536 B), the FX delay buffer (65,536 B), `parameterArray` (3,952 B), the voice structs (~3.5 KB total) and `activeParameters` (302 B); there is **no heap allocation** anywhere in the compiled engine sources, no TLS, and no zero-size writable symbols, so a snapshot/restore state swap is bounded at ~310 KiB per instance and the enumeration is provably closed. What blocks shipping it: the addresses exist only after linking, and JUCE produces four different binaries (VST3/AU/Standalone/harnesses) — each would need its own post-link symbol table (anchor-relative offsets from a known engine symbol, name+size multiset matching verified at generation time), plus a global mutex serialising processBlock across instances. A missed symbol fails silently as state bleed between instances, so the swap gets its own phase with a two-instances-alternating-blocks harness as the gate, rather than riding along with the panel.
- **tools/** — `lxr-render` (offline CLI: load kit → hit voices → WAV; our golden-test workhorse, equivalent to PHX's phx-render), render-diff script (peak/RMS/spectral comparison), intrinsics vector tests.

## Data flow / protocols
- **Parameters in:** UI knob / DAW automation / MIDI CC-NRPN → APVTS or the firmware MidiParser → parameter array → voices read parameters per block, as on hardware.
- **Notes in:** as built (Phase 1 finding — corrects the original plan): the firmware's per-voice note parameters (`PAR_MIDI_NOTE1..7`) are **inert upstream** — their `parameterArray` hooks are commented out in the firmware source and `midi_NoteOverride` is disabled — so there is no working firmware note map to read. The real firmware path is its **channel-based parser** (`midiParser_parseUartData`). The plugin therefore splits MIDI in the processor: **note on/off are intercepted** and matched in the processor — if the seven configured voice notes are not all equal, a note triggers the voice whose configured note *and* channel match, played at the played pitch; while the kit is stock (all notes = 48, the factory default), a GM map {36, 45, 50, 38, 39, 42, 46} selects the voice (7 voices incl. open hihat) and pitch = 60 + (played − map note), the same pragmatic fallback PHX-D01 used. **All other MIDI** (CC, NRPN, program change, …) is fed raw to the firmware parser, exactly as the hardware's front panel / MIDI input would deliver it — parameter edits via CC/NRPN behave bit-for-bit as on hardware, quirks included (e.g. no CC38 data-entry-fine handling after NRPN).
- **Audio out:** `mixer_calcNextSampleBlock()` fills the two DMA buffers = DAC1 (main stereo) + DAC2 (second stereo pair); per-voice routing parameters (St1/St2/L1/R1/L2/R2/FX) behave as on hardware across the two buses.
- **Rate contract:** the engine always runs at its native `REAL_FS` 44,140 Hz in 64-frame blocks. The plugin keeps a small FIFO per bus and resamples once at the boundary to the host rate (r8brain-free-src). Rationale: every EG/LFO/pitch constant in the firmware is tuned against 44,140; running the engine "at host rate" by redefining REAL_FS silently retunes the instrument (PHX-D01 runs it at a declared 44,100 and sits ~1.6 cents off). Fidelity first; the resampler costs little on drums.
- **State:** DAW project state is stored via `getStateInformation` as raw firmware bytes (versioned), so state stays diff-able against hardware files. As built (format v5, 239,546 B): the v4 body (version byte + 247 base-kit bytes + 247 morph-target bytes + morph float + 8-byte kit name + 8-byte morph-target name + 7 fader floats = 543 B; + pattern names (64 × 8 B) + song names (64 × 8 B) + the full pattern set (233,536 B, a byte copy of `seq_patternSet`) + song data (4,096 B) + a 9-byte tail (active pattern, song slot, tempo float, song-mode and ext-sync flags, Seq Pattern parameter)) + a Phase 5 block: uint32 size + a versioned sub-block (v3, 334 B: morph target B kit + name, morphX/morphY/morphXY, the 4 macro positions + 16 macro assignments, seqInfinity + 16-Pitches settings). The sub-block parses defensively (a short/corrupt block never blocks kit restore) and v1–v4 state still loads with Phase 5 settings at defaults (harness-proven both directions). One degraded path: saving before the first sequencer snapshot exists still writes the v3 layout (target B / XY / macros are then not persisted). Kit requests and SeqRequests each occupy a **single pending slot** consumed by the audio thread — callers must let blocks run between posts, or a later post replaces an unconsumed one.
- **Sequencer (Phase 3, as built):** `engine/seqbridge.c` is the only bridge to the firmware sequencer — all edits reuse the firmware's own functions (`seq_setMainStep`, `seq_clearPattern`, `seq_copyPattern`, the euklid generators) so semantics can't drift from hardware. EngineHost pumps the firmware's free-running systick in lockstep with generated engine frames (target = anchor + llround(frames × 4000/44140); `lxr_seq_pump` calls `seq_tick()` once per unit, because seq_tick advances at most one prescale tick per call), before rendering each 64-frame block — the same tick-then-render relationship as `soundengine_process()`. Transport: in a DAW, AudioPlayHead ppq/tempo drives start/stop and a muted-walk seek (`seq_nextStep()` with all tracks muted, so crossed pattern/song advances still apply) plus a sub-step phase set via `seq_MidiSyncQueue`; because the firmware tempo is integer BPM, a drift check re-seeks when host and engine disagree by more than a quarter step (fractional host tempos, loops, jumps). Standalone/internal mode uses APVTS `seqPlay`/`seqTempo`. External MIDI clock goes through the firmware's own parser → `clockSync` path when `seqExtSync` arms it. Pattern changes use the firmware pending mechanism (`seq_setNextPattern`, applied at the longest track's wrap); because the firmware's backup-buffer rule discards live edits to the pattern being left, the wrapper commits the active pattern to its backup buffer before switching and on state snapshot. One seed deviation: PAR_PATTERN_MODE is initialised to 0 ("patterns don't load kits") instead of the firmware's 1 — in the host build the mode-1 kit autoload is a stub that still switches the FX bus off first, which would kill FX on every pattern switch; mode 0 is a genuine hardware setting and the DAW owns kit state here.
- **Pattern files:** `.PAT` is the firmware's per-pattern layout ported from presetManager to stdio (3,663 B): 8-byte name + `"PatV03"` + per track: 64 step records (7 B each) + 64 timing bytes + per track/bar: uint16 LE main-step masks (56 B) + shuffle byte + 7 track-length bytes + kit number. Readers honour the firmware's version gating (no tag ⇒ V1: no timing before V3, no kit number before V2); one documented normalisation — on a short/truncated lengths block the port leaves the remaining lengths untouched where the firmware would keep stale buffer bytes. Songs are the pattern set's own memory (`seq_songData[64][64]` per kit slot; entries 0–63 pattern, 64 = stop, 65 = loop) with a `.SNG` file of 8-byte name + 64 data bytes; chaining in non-song mode is simply "the active pattern repeats" (the firmware's older nextPattern/random machinery is commented-out dead code upstream). Set export writes `pattern-NN.pat` per non-empty pattern + `song-NN.sng` into a folder; import reverses it.

## Phase 4 additions (Oct 29, 2026)

- **Reverb (as built).** Patch 03 flips `USE_REVERB` to 1: FX type value **5** ("Rev" in the panel; values 0–4 unchanged) runs the firmware's Spin-style allpass-loop reverb (`FX/Reverb.c` + VerbTools) on the shared FX buffer (≤ 28,672 of 32,769 fp16 slots — it time-shares the delay's RAM on hardware too). The only cross-effect on other FX types is the voice sources' high-quality ZDF filter being swapped for a cheaper one *while reverb is the active type* (upstream's own `#if`), so existing kits — which can never contain value 5 — are provably unaffected; the gate A/B-renders every stock kit type bit-exactly across the patch. Upstream had it disabled at every layer (the menu name is commented out, the CC is a no-op stub); the likely reason is STM32 CPU/ITCM headroom — inference, not documented fact.
- **Stem outputs (as built).** Patch 04 taps each voice inside `mixer_calcNextSampleBlock` right after its (up to) three destination distributions: the stem is the voice's own stereo contribution — post voice DSP, post performance fader, post pan — *before* the destination sums saturate and before the FX bus. Stereo and FX-bus destinations contribute the panned pair; mono L/R destinations put the full signal on that channel only; destinations pass through the same jack-availability remap as the mains. Consequence (documented semantics, not a bug): stems do not sum to the mains when the FX bus is active (the FX return is not in any stem) or when voices share a destination that saturates. Host side: `lxr_stem_data()` → 12 extra r8brain channels in EngineHost, enabled per-instance by the bus layout *latched in prepare()* so stems and mains stay sample-aligned. JUCE buses: 0 `Main (DAC1)` + 1 `Out 2 (DAC2)` (both default-enabled, as before), 2–7 `Stem Drum 1/2/3, Stem Snare, Stem Cymbal, Stem HiHat` (default-**disabled**; enable in the DAW's bus layout). Default layout is therefore unchanged for existing projects. Host-compat caveat: some hosts handle >2 output buses poorly or only expose them in mixer views — that's precisely why the stems ship disabled. The HiHat stem carries closed + open (single hardware hat voice).
- **Instance model (as built).** The engine is still one C state machine, but per-instance state now lives around it: `EngineSwap` (plugin/src) parses the *host binary's own* ELF symbol table at first use and matches it against the committed writable-globals census (`EngineCensus.generated.h`, from `tools/gen_census.py` over the engine archive: 161 symbols / 319,251 B). Validation is threefold — exact (name, size) multiset, exact byte total, three anchor globals (`seq_patternSet`, `fxBus`, `parameterArray`) landing on their true addresses — and the archive is linked whole-archive so the census universe is actually present. On success, every EngineHost owns a state blob; `activation()` guards (taken by all engine-touching EngineHost methods and by `processBlock` as a whole) serialise instances on a mutex: swap-out saves the owner's blob, swap-in restores the caller's, and a new instance starts from a pristine post-init snapshot captured at first prepare. Cost: ≤ ~640 KB memcpy per instance switch, and instances no longer render in parallel (the mutex) — the price of correctness with a globals-everywhere firmware. **Fail-safe:** any validation failure (stripped binary — the normal release case — Mach-O/PE, census drift) leaves `available()` false and behaviour is exactly the Phase 0–3 singleton. Mach-O/PE symbol walking is the known extension point. Side-fix in the same slice: the HAL RNG shim is a deterministic xorshift32 over a census global (`lxr_rng_state`), replacing `arc4random()` (process-global entropy made noise voices non-reproducible and unseparable; now they are neither).
- **CLAP (as built).** Optional target via clap-juce-extensions (pinned in `plugin/fetch-deps.sh`), wrapping the same JUCE processor — no second codebase. `CLAP_ID com.garth.elfdrumlxr`, features `instrument` + `drum-machine`. All 8 audio ports (2 mains + 6 stems) are exposed to CLAP hosts. Headless verification: `plugin/render/ClapSmokeTest.cpp`, a JUCE-free minimal host (dlopen → factory → activate at 44,140 Hz → note events → WAV).

## Phase 5 additions (Oct 29, 2026)

All Phase 5 features are host-side and work on the firmware data model only: pure functions over the 247 kit bytes (`plugin/src/KitOps.h`) and over a decoded pattern struct (`plugin/src/SeqOps.h`), applied through the processor's existing APVTS write path (kit transforms) and the seq snapshot + SeqCmd write path (pattern transforms). No parallel model anywhere; the engine and its file formats are untouched.

- **Guard philosophy (shared by mutate/breed/infinity).** The keep-set is the metadata flag union `kFlagRouting | kFlagModTarget` (the six per-voice AUDIO_OUT + PAR_FX_ROUTING; the twelve mod-target selectors + PAR_MORPH_KIT_DEST) — never written by any generative op; in a breed child it always comes from parent A, as do out-of-scope bytes (System/Global pages; scope = the six voice slices + FX page + PAR_VOICE_DECIMATION_ALL). Level floor follows the Phase 2 randomise semantics exactly: values an op *writes* on `kFlagLevel` params are floored at 30% of range; values it doesn't write keep the kit's own (INIT's transient volumes are legitimately 0). Breed applies no floor — every mutable byte in a breed child is exactly one parent's byte. All ops are deterministic xorshift32, seed-reproducible. Kit transforms push the previous kit onto a bounded lineage (32) for Undo.
- **Morph XY.** Two firmware morphs composed in a fixed order (KitOps `morphXY`): stage 1 = `lxr_morph_kit(base, targetA, round(x·255))`, stage 2 = `lxr_morph_kit(stage1, targetB, round(y·255))`. Since the firmware morph interpolates exactly at 0/255 and always keeps the *source's* keep-set, the corners are exact by construction: (0,0) = base, (1,0) = single-target A, (0,1) = single-target B, (1,1) = (0,1). The bridge uses the same composition as the kit-load path (`computeDesired` / `desiredKit` share it). When `morphXY` is on, the legacy `morph` parameter is inert.
- **Macros / CTRL-ALL / TEMP.** A macro slot stores (param, depth); assigning a slot captures an *anchor* = the param's current value and the macro's current position; moving the macro writes `anchor + round(depth × (pos − anchorPos))` clamped to the param range — so assignment itself never jumps a value, and returning the knob returns the value. CTRL-ALL resolves a panel param name+section across voices via metadata (e.g. every "Coarse"), snapshots the kit, applies one offset to all matches, and restores the snapshot byte-identically on release. TEMP is a whole-kit snapshot/recall on the same byte path.
- **Pattern access.** `readPatternData` decodes the pattern from the latest fulfilled seq snapshot (`lxr_seq_patternset_read` bytes — the same bytes state stores); `writePatternData` replays a PatternData as ≈900 SeqCmds (shuffle, lengths, setStep + setMainStep per step) through the bridge, so the firmware's own encode/clamp rules apply and the backup-buffer commit rule is honoured. Generate (per-track density, Euclidean via Bjorklund or free placement, one 16-step bar tiled ×4), Remix (rotate/thin/jitter) and groove application are pure transforms between those two calls; the editor keeps one pattern-level Undo snapshot.
- **Groove templates.** A 16-bin template {velocity scale, shift}. Extraction from a MIDI file bins note-ons to the nearest 16th (file PPQ → 24 prescale ticks/step → shift units of 3 ticks), averaging velocity (÷100) and deviation per bin; application lerps step volume/shift toward the template by a strength factor. SMPTE-timebase files are rejected.
- **Librarian + packs.** A card is a folder tree: `PROJnn` subfolders (any depth-1 folder is scanned; root files form a "(loose files)" project) with `.SND`/`.PAT`/`.SNG` classified by extension. Import routes through the plugin's own loaders (kit file → kit request; `.PAT`/`.SNG` → SeqRequest with an explicit target slot). A pack is a zip of one project folder plus `manifest.json` (`{"format": "ElfDrumLXR pack v1", "project", "author", "created", "files": [...]}`); import unpacks under a chosen root with path-traversal entries rejected and byte-exact copies.
- **Export.** Pattern → MIDI type-1 (96 tpq, 24 ticks/step): track t plays on channel t+1; a step's note sounds for 12 ticks at its velocity; p-locks are emitted at the step's tick as CC (lock nr < 128) or NRPN (nr ≥ 128: CC99 = 0, CC98 = nr − 128, CC6 = value). **Probability policy (deterministic):** a step is exported iff `hash(pattern, track, step) mod 100 < prob`, with prob 100 always and prob 0 never — the same step set on every export, and the parse-back gate compares against this exported set, which is the shared source of truth (`exportedSteps`). One-shots render each voice solo (trigger + 1.2 s capture after a 0.4 s settle gap, DAC1+DAC2 summed as the panel hears it). The stems bundle renders one 16-channel pass with GM-map hits 0.6 s apart and splits it into the 8 bus WAVs; hit timing inherits the engine's 64-frame sub-block scheduling granularity (~1.5 ms early at segment edges).
- **Infinity.** The bridge counts track-1 loop wraps; every 4th wrap posts to the message thread (AsyncUpdater), which applies `mutate(0.12, seed++)` — pendings counted while the toggle is off are discarded, not banked.
- **16 Pitches.** With the mode on, note-ons bypass the GM/configured mapping: the played note is quantised to the chosen scale (nearest scale tone, ties down) and the selected tonal voice (drums 1–3, snare) is queued at that pitch. It composes with retro-capture (quantised notes are what get recorded).
- **Retro-capture.** Note-ons that produce a hit while the sequencer runs are recorded (active pattern, track — open hat folds onto the hihat track — step index at hit time, note, velocity) into a 512-entry single-producer ring on the audio thread. Commit (message thread) merges the events belonging to the chosen pattern into that pattern via the normal write path; steps land with prob 100.
