## Morph fix (Oct 29, 2026 — Garth's Live report: "morph slider doesn't seem to work")
- **Root cause, proven headlessly before touching code:** Phase 1 made the *previously loaded* kit the morph target, so at startup the target **was** the current kit (INIT morphing into INIT) — and until a second, different kit was loaded, the slider crossfaded a kit into itself: inaudible by construction. The target was also invisible and not settable in the UI. The machinery itself was never broken, and nothing needed ticking: the plugin doesn't compile the firmware's `presetManager` (FatFs), so `preset_morph_tick` never runs — `lxr_morph_kit` + the CC edit-diff path is the one-shot equivalent, verified end-to-end.
- **Before numbers** (`plugin/render/PluginMorphTest.cpp`, new harness): startup sweep morph 0→1 — drum peaks 14631/14585/18642/20244 → 14638/14566/19949/20179, *no systematic change* (dead slider reproduced). With target = fx-dist loaded, morph 1.0 reached only 17348/15177/20204 vs a full fx-dist load's 25506/25506/25493 — see the routing caveat below before calling that a bug.
- **Firmware morph caveat (faithful behaviour, not a plugin bug):** morphing **never** touches audio routing (params 215–220), velocity destinations (149–154) or LFO targets (167–172) — the same keep-set in `preset_morph_tick` and `lxr_morph_kit`. fx-dist differs from INIT almost only in routing + FX params, so its FX routing is unreachable by morphing, on the real hardware too. A fair morph proof needs a target differing in *morphable* parameters: `tests/kits/morph-target.SND` (INIT + drum coarse pitches 95/105/100 + snare filter freq 30).
- **Proof with the fair target:** drum peak frequencies, morph 0 = **48/95/232 Hz** (== INIT full load), 0.5 = **312/595/772 Hz** (in between), 1.0 = **1975/3773/2637 Hz == the morph-target full-load reference to the FFT bin**, on the pre-fix code already — the interpolation path (APVTS poll → `lxr_morph_kit` → edit-diff CC replay) was sound whenever a distinct target existed.
- **Fix** (remote `7ce4610`): explicit morph-target loading. Processor gains `loadMorphTargetFile()` / `getMorphTargetName()`; the editor gains a **"Morph target:" row naming the target + a "Load target .SND" button**, and dropping a .SND onto the morph rows sets the target. Loading a kit still makes the previous kit the target (its name now shown). State format v2 appends the target name; v1 state still loads. After-fix `target` flow (fresh start → load target → sweep): **48/95/232 → 312/595/783 → 1975/3772/2625 Hz**, editor-facing names read `Initkit / MorphTgt`.
- **Save loose end CLOSED:** the harness `save` mode loads a kit, saves via the processor's `saveKitFile`, byte-compares and reloads: **PASS for fx-dist and morph-target** — 255 B, parameter bytes 8..255 identical, name bytes preserved, reload renders the source kit (fx-dist peaks 25506/25506/25493). No code fix was needed; it had simply never been exercised.
- **Gates after the fix:** plugin INIT @ 44,140 Hz still **bit-exact** vs the Phase 0 golden (drums 1–2 max|diff| 0 over 20,000 onset-aligned frames; drum3's peak level varies run-to-run — pre-existing voice variance, present in pre-fix renders too); `make test` green (intrinsics 28/28 + MIDI parser). Mac: universal rebuild + harness target/save modes pass on the Mac; VST3 + AU re-signed and **reinstalled**; Mac `plugin_render` peaks 13920/14585 match Linux.
- **Harness gotcha:** a headless host must pump the message loop after `loadKitFile` or `bridgeSuspended` never clears and *all* bridge edits (not just morph) silently do nothing. Real DAWs pump continuously; only the harness needed an explicit settle step — worth remembering before diagnosing another "dead parameter" headlessly.

## Firmware MIDI findings (Oct 28, 2026 — corrects an assumption in the original brief)
- The firmware's per-voice note parameters (`PAR_MIDI_NOTE1..7`) are **inert placeholders upstream**: the parameterArray hooks are commented out in the firmware source and `midi_NoteOverride` is disabled. The real mapping is **channel-based** via `midiParser_parseUartData` (a clean raw-byte entry exists and is what the plugin feeds). Factory defaults (`preset_loadDefaultGlobals`): all voice channels = 1, all voice notes = 48, global channel = 0 (all).
- Plugin behaviour, given that: if the seven configured notes are not all equal, notes match per-voice on configured note+channel and play at the played pitch; while stock (all 48) a GM map {36,45,50,38,39,42,46} selects the voice and pitch = 60 + (played − map note) — the same pragmatic fallback PHX-D01 used. All non-note, non-sysex/realtime MIDI is passed raw to the firmware parser (CC/NRPN edit parameters exactly as hardware front-panel/MIDI would).
- Firmware quirk reproduced faithfully (not a plugin bug): there is **no data-entry-fine (CC38) handling** after NRPN selection — a standard NRPN tail CC38=0 writes 0 into the selected parameter. Verified by test: NRPN CC2 #0 (filter drive 1) = 127 moved drum1 peak 13,921→23,260; a CC38 tail then zeroed filter freq 1 and silenced the kick, exactly as the firmware would on hardware.

- Note mapping (Phase 1): firmware note params are inert upstream + all-48 by default, so the plugin uses configured-note matching when the user has set distinct notes, and a GM-map fallback while stock (see MIDI findings). Deviates from the brief's "read the firmware mapping" only because the firmware mapping it describes doesn't exist in this firmware.
- Morph semantics (Phase 1): loading a kit makes the previously loaded kit the morph target; morph runs through the firmware's own `lxr_morph_kit`. **Amended Oct 29:** the target is explicit and visible — dedicated "Load target .SND" + target-name display (user-set target wins; load-kit behaviour kept as the default). The firmware's morph routing/vel-dest/LFO-target exclusions are faithful hardware behaviour and stay.
- Engine is a process-wide singleton (`std::call_once` init) — multiple plugin instances in one DAW process share the engine in Phase 1. Documented limitation in `plugin/README.md`; per-instance engines are a Phase 2+ refactor.
